Reclaiming the Codebase — Part 0: How I Lost Control of My Own Backend

A few months ago, I left my biggest personal project. When I came back, I realized I no longer understood my own backend.

Originally, around 90% of the backend code was written by me (very little AI usage). After leaving the project untouched for five months, I came back and realized I had no idea where to continue. Even my Git history couldn't help. TBH the problem wasn't AI. It started much earlier: I had no roadmap, no milestones, and development became completely random.

So what did I do? I started using AI to resume the development of the project. At first, it looked handy, making views and DB models with only a simple prompt, I told myself: MAN! I was in denial for not using Claude and for writing most of the code myself at first!

Then a problem became vivid: too many views and DB models were scripted with little review from my side, a mistake I admit and regret too much. I told myself it is time to stop being lazy and review the code at that stage. But every view depended on several functions, models, and utilities. Reviewing a single endpoint meant tracing code across the project. Django, the framework I'd been using for years, suddenly felt intimidating.

If AI made that mess then AI can understand that mess, right? That was what I told myself. And I was wrong. AI started misunderstanding the code and even edited the code blocks it generated at first. I would be talking to Claude on 2 different chats and the answers would be different. Honestly, I would not blame any AI tool for that, a clear roadmap or set of actions was not there, AI was just improvising.

Then I lost hope in the whole thing, the project I thought would be the biggest in my portfolio was over, it felt like all the effort was wasted! I tried to fix as much as I could, but procrastination kicked in. For sometime, I did not open VS Code just because the code looked INTIMIDATING. AI did not ruin the project, it just accelerated the consequences of my plan.

And here comes the role of this series, by sharing updates as I go, I will force myself to improve the code and eventually reclaim the codebase. These posts will be a commitment device, as James Clear said in his book "Atomic Habits" (amazing book btw, recommend you read it).

So as for today (August 6, 2026), the project stands on commit #102. Full repo

Every couple of days, I'll refactor one piece of the backend, explain what was wrong, what I learned, and how I fixed it. Let's see if I can reclaim this codebase!
